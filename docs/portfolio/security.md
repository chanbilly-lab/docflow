# Security model and unverified boundaries

## Identity and authorization

Cognito issues tokens to a public client using SRP. API Gateway verifies JWTs;
handlers enforce access-token use, roles, Case ownership and current assignment.
Authorization comes from trusted claims and database state, never `x-role` or a
browser-selected identity. Inaccessible Cases return 404 where specified by the
API contract to avoid disclosing their existence.

| Principal | Intended authority |
| --- | --- |
| Requester | Create and read own Cases; upload/delete/submit only in allowed states |
| Reviewer | Inspect permitted review queues; claim work; mutate assigned active task |
| Admin | Administrative inspection/allowed Case commands; must claim before review mutations |
| Backend workers | Narrow service role for their transaction, storage, queue or callback purpose |

GSI results do not substitute for current authorization. Task status, assignment,
attempt and checklist revision are fenced when committing sensitive transitions.
Conditional failures leave no partial transaction, audit or business event intent.

## Files, events and operational data

- S3 has public-access blocks, ownership controls, encryption and a TLS-only policy.
  Upload URLs sign MIME, length and create-only conditions, with a ten-minute bound.
  They are credentials: never paste them into issues, screenshots or logs.
- Keys are generated by the backend, not supplied by a caller. Soft deletion prevents
  processing resurrection but is not physical erasure of retained S3 bytes.
- Workflow tokens stay in trusted backend state/history. Public DTOs, domain events
  and allowlisted logs exclude callback internals and private document content.
- Command Lambdas do not publish business facts directly to EventBridge. Transaction
  and partition-scoped IAM is part of the design, not equivalent to a human admin role.
- Notifications resolve recipients from configured/verified identity data; they do
  not trust an arbitrary recipient supplied in a domain event.
- Secrets, raw state, credentials and test tokens stay out of Git. The frontend has
  no real credentials, and `VITE_` variables are public bundle content.

## Evidence and gaps

Five real AWS journeys and valid/missing/invalid/ID-token checks passed in the
recorded session. Broader runtime IAM denials, adversarial assignment/cursor cases,
fault injection, browser S3/CORS and delivery evidence remain incomplete. The local
browser harness tests are not AWS browser evidence. See [acceptance ledger](../CLOUD_ACCEPTANCE.md).

Not implemented as product guarantees: malware detection, full file parsing,
production frontend authentication, comprehensive compliance controls, disaster
recovery testing or production capacity validation. Do not use sensitive customer
documents for the demo. New production deployment needs a security review and
completion of the relevant skipped evidence, regardless of portfolio completion.
